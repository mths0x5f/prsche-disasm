# Run319: original MMX repeated-DWORD fill 005b0a40

The binary index records one contiguous `005b0a40..005b0aef` body of 176 bytes (`research/binary-index/ghidra/nfs5.exe-c318af393d4c/functions.jsonl:5769`). Indexed assembly in `research/v2/binaries/Porsche.exe-ddd748fdbe6d/disassembly.asm` and fresh REA Run316 attempt 002 agree on the body, two plain `RET` exits, no callees, and dispatcher caller `0053c2c7`. Dispatcher `0053c2cc` cleans the three stack arguments with `ADD ESP,0xc`, so the backend is cdecl despite any inferred stdcall signature. No accepted production owner of `005b0a40` existed before this run.

The original takes `(destination, repeated DWORD value, byte_count)` in EAX/EDX/ECX. If unaligned, it peels low byte, low word, and optionally a DWORD according to the **updated** address bits and signed count comparisons (`005b0ab2..005b0aeb`). It then executes `MOVD MM0,EDX; PUNPCKLDQ MM0,MM0` (`005b0a53..005b0a56`) even when count is zero, writes four MMX qwords per 32-byte iteration (`005b0a59..005b0a75`), writes further qwords in 8-byte steps (`005b0a77..005b0a85`), and finishes with DWORD/word/byte stores (`005b0a87..005b0ab1`). It returns the advanced pointer in EAX and **does not execute EMMS**. The caller dispatcher does that after the MMX call (`0053c2cf`); direct calls retain dirty MMX/x87 state.

`005b0a40.cpp` defines Run312's canonical void game contract `heap_fill_mmx_005b0a40(void*, uint32_t, uint32_t)` and a typed `heap_fill_mmx_005b0a40_core` to expose EAX. These are two C++ views of **one original function**, not two recovered PE bodies. The implementation uses MMX intrinsics and deliberately leaves MMX state dirty. MSVC warning C4799 (function does not call EMMS) is expected and recorded in `compile.log`. No global provider or original instruction bytes are in production source. The game object has zero undefined external symbols.

`py -3 scripts/research/verify-v2-mmx-fill-319.py` reads the immutable PE, places its exact 176 bytes in private RW memory, changes it to RX, then executes original bytes and recovered C++ on a normal-CRT Win32 fixture.
