# libtiff 3.4 in gimme.dll

Unmodified `libtiff/` files from `tiff-v3.4-tar.gz`
(https://download.osgeo.org/libtiff/old/tiff-v3.4-tar.gz, SHA-256
`c77eb9a7b04a2f129ea72633ef954f3107ea5a2ff0cd13115a731705dfdbae1d`; dist/tiff.alpha 033);
licence in `COPYRIGHT`. The `tiff\` directory is attested by the assert paths
`tiff\tif_write.c`, `tiff\tif_read.c`, `tiff\tif_dirinfo.c`, `tiff\tif_fax3.c`.

- `tif_fax3sm.c` is generated by this release's `mkg3states -c const`; its three tables equal the
  binary's bytes at file offsets 0x41c024, 0x41c224, 0x420224.
- Default `tiffconf.h` (None, LZW, PackBits, ThunderScan, NeXT, CCITT; JPEG/ZIP/PixarLog/JBIG
  NotConfigured, as the binary's codec table at 10441bd0 shows). Built with `_WINDOWS`
  (`sizeof(TIFF)` 0x1e0, as TIFFClientOpen 10189a10 allocates). tif_print.c, tif_version.c and the
  platform files are not linked; EA's platform layer is `../tifgstream.cpp`.
- Version: strings exclude betas ≤029/031 ("PixarLog" codec name, beta032+) and 036/037 (old
  read-error messages); Fax3Decode1D 1020ae6d uses `ClrBits(1)` in SYNC_EOL (1020b056), which
  beta034/035 changed to `ClrBits(11)`. 3.4 (alpha 033) and beta032 compile to the same code for
  the linked files.
